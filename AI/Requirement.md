Create the `Requirement.md` file for the React.js marketing landing page project.

This document must define WHAT the website must provide.

Do not describe detailed implementation methods.

Do not describe specific React component structures.

Do not describe CSS implementation.

Do not define coding conventions.

Do not define security implementation.

Those concerns belong to other Markdown files.

Organize the requirements into clear categories.

Include the following functional requirements:

1. Navbar
2. Hero
3. Marketing Services
4. Why Choose Us
5. Marketing Process
6. Marketing Results
7. Client Logos
8. Study Cases
9. Study Case Detail
10. Testimonials
11. Testimonial Detail
12. FAQ
13. CTA sections
14. About
15. Footer
16. Consultation Booking
17. Responsive behavior
18. Accessibility
19. Loading states
20. Lazy loading
21. Navigation

Define the Hero requirements:

* Strong Perth and Western Australia marketing positioning
* Clear marketing value proposition
* Primary CTA
* Secondary Case Study CTA
* Marketing-related visual
* Trust indicators

Define the Services requirements:

* Approximately five marketing services
* Service cards
* Service descriptions
* Service detail CTA
* View all services CTA

Define the Study Case requirements:

Each case study should contain:

* Industry
* Business challenge
* Marketing objective
* Strategy
* Services used
* Implementation
* Results
* Image
* Detail CTA

Define the Testimonial requirements:

* Customer name
* Role
* Business
* Avatar
* Rating
* Review
* Optional results
* Detail CTA

Define the FAQ requirements:

* Marketing-related questions
* Accordion behavior
* Accessible interaction

Define the booking requirements:

Step 1:
Select date and time.

Step 2:
Select marketing service.

Step 3:
Enter personal information.

Step 4:
Review information.

Step 5:
Confirm.

Step 6:
Show success state.

Calendar requirements:

* Working hours: 09:00–17:00
* 30-minute intervals
* Valid appointment start times from 09:00 through 16:00
* 16:30 must not be selectable
* Invalid time selections must be prevented

Personal information should include:

* Full Name
* Email
* Phone Number
* Business Name
* Optional Message

Define validation requirements.

Define responsive requirements for:

* Desktop
* Tablet
* Mobile

Define performance requirements:

* Lazy loading for appropriate below-the-fold images
* Loading states
* Skeleton states where appropriate
* No unnecessary layout shifts
* Hero media should load immediately

Define accessibility requirements.

Define SEO-related functional requirements.

Clearly separate:

* Functional requirements
* UX requirements
* Performance requirements
* Accessibility requirements
* SEO requirements
* Content requirements

Use unique requirement IDs such as:

REQ-NAV-001
REQ-HERO-001
REQ-SERVICE-001
REQ-BOOKING-001

Every requirement should be specific, testable, and unambiguous.

Do not write implementation code.
